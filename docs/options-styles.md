# 规则设置页样式维护

所有规则设置页样式集中在 [rules.css](../public/options/rules.css)，按以下七个分区组织。组件修改放到对应分区，不在文件末尾追加覆盖。

- Tokens：字体、颜色和间距变量，基础排版及减少动画设置。
- Controls：按钮、开关、设置行、提醒外观和设置组。
- Layout：设置页外壳、页签和正文区域。
- Tables：片段分类与动态分类表格。
- Examples：行为矩阵、卡片预览、操作模拟器和规则目录，分区内按组件分组。
- Legacy adapters：从旧页面移动过来的控件适配，以及旧版 DOM 的排版修正。
- Onboarding：邀请气泡和欢迎弹窗。

## 间距与控件

通用尺寸在文件开头的 Tokens 分区定义：

```css
--rules-space-heading: 12px;
--rules-row-gap: 4px;
--rules-column-gap: 24px;
--rules-control-height: 32px;
```

标题到内容的距离由标题容器控制，设置行之间用 `gap`。避免用空行元素或多个相邻 margin 共同撑出间距。实际文字对齐还取决于控件高度和行高，因此修改后需要看渲染结果。

这些变量有明确用途，不能把所有相同数值都替换成同一个变量。例如卡片内边距与标题间距即使同为 12px，也应分别维护。

## 层叠关系

`options.html` 先加载旧版 `options.css`，再加载 `rules.css`。文件内的通用控件样式先于页签按钮，旧控件适配放在组件样式之后。

当前样式没有使用 `@layer`，以保留与未分层旧样式的优先级关系。不要单独给一个分区套层，也不要随意调换分区顺序。

同一组件的普通状态、交互状态和响应式规则放在同一节。修改已有定义，不在文件末尾再写一个同名选择器。重复声明合并前，要检查属性简写、选择器优先级和媒体条件，不能只按字符串去重。

旧版适配中的 ID 和结构选择器用于兼容现有 DOM。新增组件优先使用专用 class；不要把修正旧控件的规则扩散到全局。`[hidden]` 和减少动画的 `!important` 是有意保留的约束，不用于修补普通布局。

## 验证

运行 `npm run build:dev` 后，按 [Playwright 指南](playwright-e2e.md)检查设置页与引导流程：

```bash
npx playwright test e2e/rule-settings.spec.ts e2e/rule-rollout.spec.ts
```

外观重构还应保存修改前后的截图，使用相同配置、滚动位置和交互状态，对比明暗主题与宽、中、窄三种窗口。动态与评论、声音等折叠设置需要展开；长页面要检查滚动后的内容。功能测试通过不能代替视觉对比。
