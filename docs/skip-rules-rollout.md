跳过规则引擎与灰度发布草案

日期：2026-09-25。行为依据：`skip-behavior-matrix.md` 及用户随后确认的六项规则。本文保留方案与分阶段发布边界。第一版规则引擎及手动灰度切换现已接入；实现位置、启用方式和已验证范围见 `skip-rules-implementation.md`。

目标是让每次决定都能回答三个问题：哪个片段、为什么采取这个操作、对应哪条产品规则。复杂度主要来自跨事件的状态和多个片段之间的关系，仅把现有条件搬成一长串配置不能解决这些问题。

建议用普通 TypeScript 编写有名称、有类型、有测试的规则，保留 Markdown 决策表作为评审入口。第一阶段无需通用规则框架、可执行远程脚本或新的规则描述语言。

1．行为与规则分层。

| 层次 | 输入 | 输出 | 边界 |
| --- | --- | --- | --- |
| 操作与经过识别 | 视频身份、操作来源、拖动前后位置、暂停/播放状态 | 每个片段的外→内、内→内、内→外、未进入，以及对应经过 | 撤销和预览不是普通用户 seek；视频播放造成的越界也不同于拖动 |
| 片段规则 | 有效分类策略、片段动作、本次排除、编辑开关、明确用户操作 | 每个片段允许什么、不允许什么及原因 | 单段判断不操作 DOM、计时器或视频 |
| 多片段规划 | 各片段决定和有效区间 | 实际跳转范围、快进范围、静音范围、逐片段卡片状态 | 只合并仍被授权的范围；跳过和静音可以并存 |
| 执行与反馈 | 已选引擎的计划、当前播放器实际状态 | 实际操作及成功/失败反馈 | 同一时刻只有一个执行方；根据实际反馈报告完成 |
| 提示展示 | 每段的业务状态和卡片显示设置 | 卡片原地更新、入场、完成退出 | 展示退出不能冒充用户取消；计数不依据卡片 DOM |

规则和状态转换应当是确定性的：输入相同快照和事件，得到同样结果。视频时间、单调时钟和配置都作为输入提供；纯规则内部不读取全局配置、页面、网络或 Date.now。

规则引擎需要保留简单的会话状态，并非所有规则都能是无状态条件。例如“本次已排除”和“暂停期间尚未处理的进入”必须跨事件保留。它们可以通过纯状态转换表达，无需把播放器对象放进规则中。

2．可以直接阅读和测试的规则目录。

| 编号 | 条件/用户操作 | 决定 | 关键回归 |
| --- | --- | --- | --- |
| LIFE-01 | 计划所属视频/分 P/播放实例已失效 | 不执行旧操作 | 切视频后旧请求、旧定时器返回 |
| USER-01 | 主动关闭或隐藏某张卡片 | 排除对应片段的本次经过，移除其当前处理贡献 | 快进中关闭、预告关闭、完成后关闭 |
| USER-02 | 完成倒计时退出、堆叠遮挡、页面卸载 | 只处理展示，不建立用户排除 | 退出动画不误取消片段 |
| USER-03 | 撤销某段 | 定位到对应片段起点并防止立即重新自动处理 | 撤销 B 不回到合并任务 A 的起点 |
| USER-04 | 明确点击跳过 | 立即定位到所选目标终点，保持原暂停/播放状态 | 全局快进开启时也立即跳过 |
| PLAY-01 | 视频暂停/缓冲，且没有明确定位命令 | 不执行新的自动播放操作，可更新片段与卡片状态 | 暂停时拖动不会自动跳走 |
| PLAY-02 | 恢复播放 | 以最终位置、最新数据和尚有效的进入意图重新判断 | 外→内→外不补跳；外→内→内仅处理最终进入 |
| ENTER-01 | 普通用户从某段外进入该段内 | 按段内进入设置与该段策略判断，方向不影响 | 向前与向后进入同样处理 |
| ENTER-02 | 普通用户在同一片段内拖动 | 不追加跳过，不重新启动用户已取消的快进；更新有效范围 | 多次 seeking 不重复执行，不重置卡片 |
| ENTER-03 | 离开片段 | 结束该次经过与不再有效的处理贡献 | 恢复声音/速度；再次进入可重新判断 |
| ENTER-04 | 插件撤销、预览、处理后衔接 | 使用对应操作语义，不套普通拖动规则 | 撤销不重跳，相邻第二段不遗漏 |
| EDIT-01 | 编辑中且不包含其他片段 | 只允许已明确授权的目标预览 | 其他段不打断编辑定位 |
| EDIT-02 | 编辑中且包含其他片段 | 其他段按各自策略参与 | 不能把手动、标记、排除的段升级为自动 |
| POLICY-01 | 自动/手动/仅标记/忽略 | 分别允许自动处理、显示操作、只显示标记、不参与 | 全部 16 种相邻分类组合 |
| POLICY-02 | 本次经过已排除 | 不再生成该段操作或主动提示候选 | 暂停、段内拖动、片段数据刷新不解除排除 |
| PLAN-01 | 多个仍有效的自动跳过范围相接/重叠 | 合并播放操作，保留每段状态与身份 | 快进不断速、每段仍独立交接卡片 |
| PLAN-02 | 排除某个合并成员 | 从剩余有效成员重新计算范围 | 不能继续执行排除前的旧终点 |
| PLAN-03 | 静音与跳过/快进同时存在 | 分别遵守策略和用户选择，组合执行 | 不丢失声音恢复责任，不越权静音手动段 |
| UI-01 | 同段同次经过状态变化 | 更新原卡片，不做新卡片入场 | 预告→进行中→完成不闪烁 |
| UI-02 | 全局设置不展示卡片 | 只影响展示，不产生片段排除 | 无卡片仍按既定策略播放 |

规则不能全局“第一条命中就返回”。视频资格和自动执行门槛先判断；逐段决定之后再合并播放操作；卡片状态独立输出。否则一个片段的内→内拖动会阻断另一个片段的外→内进入，或“暂停”规则会连必要的卡片更新一起吞掉。

明确用户命令与被动自动行为也要分路：PLAY-01 限制的是自动执行，不拒绝用户暂停时点“跳过”的明确定位。用户排除必须先参与规划，不能在合并终点已经算好之后只把卡片隐藏。

每条规则至少保留稳定编号、说明、适用条件、结果和用例。新增规则必须说明与同阶段其他规则是否互斥；组合结果存在冲突时报告冲突，不能靠文件顺序悄悄覆盖。

3．单次经过和几个关键例子。

同片段内连续拖动仍属于同一次经过。自然离开或用户拖出后再次进入才是新的经过。经过、执行任务和卡片不是同一个概念：一次合并任务可以涉及多段经过，每段都有自己的卡片。

| 场景 | 应有结果 |
| --- | --- |
| A=[10,30]，15→25 | 对 A 为内→内，不追加处理 |
| A=[10,30]，35→25 | 对 A 为外→内，按策略判断，虽然方向向后 |
| A=[10,30]，B=[20,40]，15→25 | A 内→内，B 外→内，各自判断 |
| A 内关闭卡片，之后仍在 A 内拖动 | A 本次保持排除 |
| 关闭 A 后离开，再进入 A | 新一次经过，可以重新处理 |
| A 的预告被关闭 | 保护即将发生的一次经过，不能因尚在段外立即清除 |
| A 完成卡片自动退出 | 不生成用户排除 |
| A、B 相邻快进，关闭唯一正在生效的 A | 从当前点停止 A 的快进贡献；到 B 再按 B 的规则判断 |
| A、B 重叠且都已有效，关闭 A | 建议仅排除 A；B 仍可支持快进或静音，不强制错误地恢复状态 |
| 暂停时从 A 拖到 B 再拖到段外 | 卡片随落点更新；恢复时不执行 A/B 的历史计划 |

独立重叠 B 的范围是否应保护被关闭 A 的内容，仍是“排除片段”与“保护时间范围”的产品区别。本文建议只排除 A，不自动扩大为取消 B。撤销的重叠防重跳范围另行确认。

4．输出要能解释，副作用只能执行一次。

调试视图可以展示一条决定，例如“B：外→内；手动分类；显示跳过按钮；没有移动进度”。同一条记录应能定位到 ENTER-01 与 POLICY-01，以及对应行为矩阵用例。

建议输出分为以下内容，而不是一个 autoSkip 布尔值：

- 下一份经过/排除/任务状态。
- 每个片段的候选结果、命中规则及未执行原因。
- 需要执行的定位、倍速和静音操作，以及可合并的有效范围。
- 每个片段应展示的卡片状态。

“计划跳过”不能直接等于“已经完成”。实际定位失败、数据变化或视频切换会使计划失效；执行反馈后才确认结果和统计。重复媒体事件、重排或重复规则评估不能重复移动进度、重置完成卡片倒计时或重复计数。

播放器操作仍需要专门处理 B 站事件时序、缓冲、计时精度和状态恢复。规则引擎让业务判断集中可见，并不承诺消除所有异步复杂度。

5．灰度期间只允许一个行为执行方。

建议分为三个运行模式：

| 模式 | 谁真正执行 | 新规则的作用 |
| --- | --- | --- |
| legacy | 旧逻辑 | 不参与 |
| shadow | 旧逻辑 | 仅计算决定和本地差异，不跳转、不改速、不静音、不发卡片或统计 |
| rules | 新逻辑 | 按新规则执行，旧逻辑不得再保留能执行操作的监听器或定时器 |

保留旧逻辑作为回退时，需要一个共同的选择边界。第一阶段可以由边界选择完整的旧流程或新流程；逐步抽取后，再共享唯一的播放器执行入口。不能为了快速灰度同时注册两套有副作用的调度器。

模式在视频会话开始时选定并保持稳定。不能按片段、按每次事件随机分组，否则前半段使用旧的取消语义，后半段又使用新的卡片关闭语义。

用户主动切回旧版或紧急停用新逻辑时，应先取消旧模式的未完成任务、使旧异步回调失效，并只恢复该模式仍拥有的播放器状态。保留当前已经承诺的本次排除和取消意图；如果旧版无法表达，就先停止这次自动处理，到下一个视频再使用旧模式，不能立刻重跑旧调度把用户跳走。

6．分阶段放量。

| 阶段 | 用户范围 | 放行依据 |
| --- | --- | --- |
| 行为用例与离线回放 | 开发验证 | 确认规则表；逐条覆盖相邻/重叠/暂停/关闭卡片语义 |
| 本地 shadow | 开发与自愿测试者 | 新决定可解释；没有第二套副作用；能导出最小复现记录 |
| 手动开启 rules | 自愿测试者 | 实际 B 站视频、Windows/Linux、快进/静音/编辑和原生快捷键通过 |
| 小比例稳定分组 | 少量用户 | 没有取消失效、正常内容被快进、静音残留或播放器操作受阻等回归 |
| 扩大比例至默认启用 | 逐批扩大 | 关键行为回归稳定、故障和回退反馈可接受，保留旧模式回退窗口 |

5%→20%→50%→100% 仅是可选放量示例，不是现在已经有的发布能力或固定发布计划。最初用本地实验设置即可，没必要先建设复杂平台。若之后接入远程比例控制，应使用稳定的本地分组种子，不按视频、时刻或每次刷新重新抽签；远端配置只选择已打包模式和比例，不下发执行脚本。

默认模式、配置不可用时的行为和回退方式需在每个发布阶段明确。远端配置变更也只在安全边界生效，不能正在快进时突然更换引擎。

shadow 的差异分为“预期产品变化”“兼容偏差”“执行资格错误”。本次明确改变了关闭卡片的语义，所以新旧输出不同是正常的，不能以零差异为目标。只比较同一份操作前快照；真实视频继续由旧流程推进时，不能把新引擎在假设时间线上的后续结果当作已验证事实。

调试记录优先本地、有限容量、用户主动导出，记录规则编号和最小时间范围即可。不得顺便增加默认上传观看记录；若需要线上指标，另行明确采集范围和用户选择。

7．下一步的工作边界。

先按已确认规则建立可读的测试矩阵和记录格式，再抽出纯规则与多片段规划；新引擎先在隔离输入上验证，保留旧版默认。完成模式互斥、任务失效与回退检查后，再开放自愿用户测试。

还未确认的细节包括：编辑开关默认值、撤销与关闭涉及重叠片段时的保护范围、卡片“暂停快进”按钮针对当前段还是整次连续任务、全局不展示卡片时手动入口的位置。不能把这些通过某个规则优先级暗中决定。

当前实现默认使用旧版，提供手动选择 legacy/shadow/rules，刷新视频页面生效。比例放量、远程开关和自动线上差异统计仍是后续方案，本次未部署远程服务、未面向所有用户启用新版、未创建 PR。
