# 可配置规则与固定行为

规则页面以“处理方式 × 本次状态 × 操作”为中心。分类只提供片段的初始策略，用户意图、视频状态和显示设置分别影响后续决定。页面不能提供项目里不存在的开关。

## 用户实际可以配置什么

| 配置 | 实际范围 | 现有字段 |
| --- | --- | --- |
| 分类处理方式 | 自动、手动、仅标记、忽略；不是逐片段单独保存偏好 | categorySelections |
| 快进替代直接跳过 | 全局作用于自动区间；不足 0.5 秒和草稿预览仍直接跳转 | enableSpeedUp |
| 快进速度 | 设置页提供 2、3、4、6、8、16 倍 | speedUpPlaybackRate |
| 用户从外部拖入是否触发 | 前方和后方进入共用；不影响段内拖动保留意图 | skipOnSeekToSegment |
| 暂停时进入片段后恢复 | 按片段设置处理，或本次改为手动；仅规则引擎 | skipResumeAction |
| 快进暂停后恢复 | 继续快进，或取消本次快进并保留卡片；仅规则引擎 | speedUpResumeAction |
| 片段前预告 | 开关与提前的视频秒数 | advanceSkipNotice、skipNoticeDurationBefore |
| 已完成提示停留 | 实际显示时间；不把进行中的卡片改成独立倒计时 | skipNoticeDuration |
| 显示卡片 | 全局隐藏不取消跳过；用户点击卡片关闭另行处理 | dontShowNotice |
| 卡片外观 | 完整、迷你及淡化模式，在现有展示层处理 | noticeVisibilityMode |
| 编辑时包含其他片段 | 隔离编辑目标或保留其他片段处理 | previewIncludeOtherSegments |
| 音乐视频、全片标签策略 | 保留现有覆盖顺序，并记录覆盖原因 | autoSkipOnMusicVideos、manualSkipOnFullVideo |
| 静音许可、最短时长 | 第一层片段资格，独立记录排除原因 | muteSegments、minDuration |
| 全局停用、白名单 | 执行资格限制 | disableSkipping、whitelistedChannels、forceChannelCheck |

当前快进仍是全局开关，不能在分类选择中把 A 单独设为直接跳过、B 单独设为快进。原型的快进页签展示“自动 + 全局快进”的组合。逐类独立快进需要单独设计配置迁移和旧调度器兼容，不能把它当成已经支持。

原型里先前提供的“等待卡片固定 8 秒后隐藏”已移除。项目没有这个设置，也没有让用户任意选择每种状态使用视频时钟还是显示时钟。

弹幕来源不纳入此次规则模型、配置页面和新增测试。runtime 保留原有兼容分支，不扩展该功能。

## 不开放为开关的行为

- 视频暂停或缓冲时，不自动跳转或启动快进；恢复播放时只判断最终位置。
- 明确点击跳过立即执行。暂停时点击仍可跳转，但不自动播放视频。
- 段内拖动保留取消、回看、关闭和用户改倍速的意图。
- 关闭只排除本次经过。离开后重新进入才重新判断；预告取消作用于即将到来的一次经过。
- 撤销回到对应片段开头，并保护直接重叠的自动成员，避免立即再次跳走。
- 用户主动改倍速后交还控制权；插件只恢复自己拥有的速度。
- 相连、重叠且允许自动跳过的成员可以合并跳转。每个成员仍有自己的卡片，不跨越正常内容间隙。
- 预告和进行中卡片跟随媒体边界；完成卡片按显示时间退出，悬停不重置剩余时间。
- 只有执行成功反馈才标记跳转完成。显示到期和全局隐藏不等于用户关闭。

这些是简单规则共同遵守的约束。用户配置改变输入，不改变规则优先级，也不开放矩阵里的每个格子单独配置。

## 如何组合

例如“用户拖入一个自动片段”按以下次序计算：

1. 从原始分类策略和视频事实计算有效策略；再判断是否从片段外进入，段内移动保留旧经过。
2. 检查拖入设置，以及本次是否取消、关闭、回看或由用户接管倍速。
3. 检查暂停、缓冲、编辑隔离和全局禁用。
4. 自动执行获得允许后，依据全局快进设置、片段动作和长度选择跳转、快进或静音。
5. 合并允许跳转的相连成员；执行反馈确认各成员是否完成。
6. 为每个片段生成卡片阶段、可见性、时钟和命中原因。

“自动片段”因此不是永远执行跳转的命令。它只是获得自动执行资格的一个条件。

## 第一层策略归一化

`evaluateRules` 的第一步调用 `prepareSegmentPolicies`。输入仍是分类的原始策略，不把上一轮的有效策略写回分类配置。执行顺序为音乐视频自动处理、同类别全片标记改手动、最短时长排除、静音许可、隐藏或外部来源排除。每一步留下独立规则编号。

这一层回答“这是什么片段、按设置应如何处理”。进入方式、暂停/缓冲、本次取消、关闭、撤销、用户调整倍速、编辑预览仍由后面的规则处理。改变第一层设置不会清除本次经过里的用户意图，明确点击跳过仍走显式操作。

后台返回原始候选 `rawSegments` 和用于原有展示/调度的 `segments`。两者来自同一份缓存，不增加网络请求。加载时按当前视频和 CID 选择数据，在发布前应用用户隐藏、差评和本地分类修改。新引擎从完整候选计算策略；旧引擎继续使用原有展示集合。

显示全片图标的开关不会再决定引擎能否看到全片标记；静音开关关闭时也保留原始静音候选。修改静音许可时，规则立即重新判断，数据刷新负责同步弹窗列表和进度条。修改最短时长时，同步重算展示隐藏标记，且只清除 MinimumDuration，不清除用户隐藏或差评。

最短时长的提交确认仍属于投稿模块。暂停时可以释放已经失去资格的倍速或静音，但不启动新的自动操作。

对照和操作测试增加普通、音乐、全片标记、音乐与全片组合、静音等示例条件。它们只构造输入，使用同一个 `evaluateRules`；四个真实偏好通过同一个 `policyPreferences` 读取。

## 项目中的职责

| 文件 | 职责 |
| --- | --- |
| preferences.ts | 把真实配置映射为规则输入，runtime 和原型共用 |
| policy.ts | 引擎第一阶段：从原始分类、片段和视频事实计算有效策略，组合音乐、全片手动、最短时长、静音许可和来源排除 |
| visits.ts | 进入、段内移动、退出和成功反馈，维护本次经过 |
| resume.ts | 记录实际视频暂停，按当前经过应用恢复偏好；缓冲结束不触发 |
| intents.ts | 明确用户命令与重叠保护，在投影任何播放效果之前应用 |
| rules.ts | 有序的执行资格规则，以及每条规则对应的真实配置键 |
| playback.ts | 选择执行方式、暂停限制和现有倍速算法 |
| cards.ts | 生成阶段、是否展示、媒体或显示时钟，并记录原因 |
| planner.ts | 合并已获准的区间 |
| engine.ts | 按顺序组合以上规则，返回纯数据计划 |
| runtime.ts | 读取实际页面，执行播放动作，确认结果，发布卡片 |

`ruleDefinitions` 的配置字段使用实际 Config 类型检查。空配置列表表示固定行为。页面读取这份目录，不另行宣称某条规则可以配置。

逐片段状态区分取消预告、撤销回看、取消快进、用户改倍速和关闭。展示阶段仍复用原有卡片类型，避免因内部状态细分而更换卡片实体。

卡片计划保留 `deadline` 供现有接口使用，同时提供显式 `clock` 描述。组件消费 `clock` 决定媒体边界；完成卡片的实际时长仍读取现有设置。`show` 只影响发布，不删除完成状态或统计所需的计划。

## 这次整理修正的交互

1. 重叠快进时，用户改倍速原先逐张卡片取消，第一张取消后其他成员可能又申请快进。现在用一次用户速率事件同时处理所有受控成员。
2. 撤销重叠片段原先在部分播放效果计算之后才设置保护。现在先更新所有意图，再计算快进、静音和卡片。
3. 全局隐藏期间原先仍缓存“已发布”卡片，恢复显示后同状态卡片可能不再发布。现在显示资格参与计划，隐藏时移除发布缓存，恢复后可以重新出现。

不改变默认灰度模式，不新增分类快进选项，不改变现有倍速算法。后者在配置速度与基准速度相同时会取两者之和，上限 16 倍；本次仅抽取并复用，原型也遵守这一行为。

## 插件设置页

行为页顶部只有一个“启用新版规则引擎”灰度开关，写入已有的 skipEngineMode。开启时显示新规则页面并使用 rules 引擎；关闭时恢复经典行为页面并使用 legacy 引擎。配置页面和执行引擎共用这一状态，没有独立的页面版本按钮或三档选择器。引擎切换即时作用于已打开的视频，默认模式不变。切换时先释放旧引擎的计时器、倍速、静音和卡片，再按当前位置交给新引擎；暂停时不会自动定位或启动快进。

左侧沿用“行为”入口。灰度开启后，右侧开关下方显示五个标签：

- 片段设置：集中片段跳过、卡片提醒和频道白名单配置。复用原分类组件、原生选项控件及同一个 DOM 实例；保留颜色、说明、依赖显隐、确认弹窗和保存逻辑。切回原页面时归还控件，避免重复 ID 或两份状态。
- 标签与过滤：视频标签及封面显示、动态与评论区商品链接过滤，按两组展开显示。
- 行为对照：按已保存的设置计算状态与操作矩阵，显示卡片、时钟和命中规则。设置入口返回第一个标签，不重复放置表单。
- 操作测试：模拟视频输入及执行反馈，包含暂停、恢复、缓冲、拖动、倍速、失败、单个/相连/重叠片段、卡片操作和最近 30 条记录。载入预设场景不修改分类或全局快进开关。
- 规则说明：搜索和筛选规则，展示相关设置，支持从处理结果跳入并返回。

实现位于 src/options/rules。RulesPage.tsx 管理视图、配置订阅和测试状态；SettingsPanel.tsx 读写 Config；model.ts 只准备示例输入、模拟播放器 I/O 和显示时间，直接导入实际 evaluateRules、倍速计算和 NoticeClock。所有标签使用同一个实际引擎，不打包之前 /tmp 下的 demo 脚本。

NativeOptions.tsx 在页面可见时移动原控件，并用位置标记在离开页面时还原。旧行为页的所有 data-sync 项都有对应的新页面入口，浏览器测试逐项检查覆盖；视频标签和内容过滤放在“标签与过滤”页，快捷键保留在左侧原有“快捷键”页。

| 来源 | 新页面位置 |
| --- | --- |
| 分类、颜色、音乐视频例外 | 分类表格 |
| 倍速、拖入、暂停恢复 | 行为与提醒设置 |
| 静音、提示音、最短时长、整段手动、频道检查 | 分类表格下方 |
| 灰度开关 | 行为页顶部，新旧页面共用同一个开关 |
| 整段视频标签及封面显示、动态与评论区屏蔽全部子选项 | 标签与过滤 |
| 无权限类别 | 片段设置，分类表格下方 |
| 提醒显隐、提前预告、计时、提醒可见方式 | 行为与提醒设置 |
| 全局跳过开关、编辑预览包含其他片段 | 行为与提醒设置 |
| 频道白名单 | 片段设置，下方可展开区域 |
| 跳过/精彩时刻/关闭提醒快捷键 | 左侧原有快捷键页 |

提示音由新旧引擎复用同一个执行器。自动跳过成功和新快进片段开始时触发；草稿预览、用户手动跳过、静音和重复轮询不触发，音频播放失败不影响跳过。

公共样式限定在规则页面内，并排除原生控件，沿用 options.css 的颜色、字体和控件。页面遵循深浅主题及减少动画设置。规则页面与原设置页共享配置，并同步普通控件及依赖选项的显示状态。分类颜色仍由原组件保存。

内部标签使用 rulesTab 查询参数保存位置，外层统一使用 #behavior。旧的 #skip-rules 链接只重定向到行为页，不会开启灰度。离开操作测试或切换左侧入口会停止模拟计时，测试状态保留。组件订阅、观察器和计时器都有清理路径。

独立原型保留在 /tmp/bsb-rule-behavior，供设计对照，不作为插件资源提交。模拟卡片展示行为结果，不替代真实视频页的卡片组件。

## 验证边界

单元测试覆盖规则组合、卡片时钟、隐藏不取消播放、重叠用户速率释放、撤销保护，以及策略覆盖顺序。浏览器回归覆盖灰度引擎、卡片外观、快捷键、生命周期，并新增重叠改倍速和同次经过重新显示卡片的场景。

类型检查使用 `tsc --noEmit --skipLibCheck`。未加该选项时，现有依赖的声明文件有 React 默认导入和 Node Buffer 类型错误；本次没有修改依赖配置。构建与 ESLint 分别验证项目代码。

## 恢复播放偏好

两个新选项默认继续原有行为，只在规则引擎模式执行。暂停期间进入普通跳过片段，记录为尚未处理；已经快进的片段暂停，记录为快进暂停。实际恢复后应用对应选项一次，当前经过内继续保留决定。

从暂停进入缓冲时保留待判断状态，到视频真正可以播放时再执行。只有缓冲而没有暂停不会触发此偏好。明确点击跳过仍立即执行；暂停时明确恢复快进也优先于该设置。关闭、撤销、用户改倍速等现有意图不会被恢复偏好清除。

原型的两个选项默认展开，选择后定位到“暂停与恢复”矩阵。操作测试的预设场景保留恢复偏好，暂停状态下修改偏好也会用于随后恢复。
