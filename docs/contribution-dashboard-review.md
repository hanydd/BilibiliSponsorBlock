# 贡献页上线审查

审查日期：2026-10-30。

此前实现不能直接上线。审查发现的代码问题已修复；实际发布仍须完成服务端迁移、配置、镜像回源和 CF 规则验证。没有部署本次改动，也没有创建 PR。

## 已修复的问题

- 限流复用项目的代理 IP 识别和 Redis store，使用独立前缀。避免所有经 Nginx 的用户共用一个来源 IP 额度。只有这个只读接口允许限流 store 失败后继续，数据库并发保护仍生效。
- 镜像 Nginx 示例增加 contributionStats 的 GET/HEAD 主站回源。客户端统计请求允许备用节点重试，但不会因统计繁忙改变视频查询的全局节点状态；增加请求超时、正文大小限制。
- 响应增加 apiVersion 和完整结构校验，包括公开用户 ID、年份、日期、数值、分类和排行。拒绝串用户的缓存、错误类型和过大数据。后台无响应时 Promise 会拒绝，不再无限加载。
- 页面在账号、服务器配置变化后自动重载；返回页面和跨北京时间午夜时更新。今日提交独立于所选日历年份。
- 排行通过已有 videoInfo 表批量读取标题、CID 和分P。分P已知时定位正确分P；未知时打开视频首页并提示，不默认跳转第一P的相同时间。
- 配置拒绝模糊日期和未来采集起点。保持首日/今日部分数据、未采集日期为 null 的规则。线上存储的 service=YouTube 已作为正式查询口径，而不是演示数据自定义值。
- 修正连接池未满时误报繁忙的判断。数据库真正饱和时返回不可缓存的 503，缓存命中不占计算额度。
- 修复复用 Redis 组件时触发的初始化竞态：缓存连接 ID 未取得时不发送 tracking 命令，异步 tracking 失败不会成为未处理异常。已有缓存行为由完整回归覆盖。
- migration 17 支持同名索引预建，迁移测试验证已有日统计不丢失。既有版本断言更新至17。没有修改 SQLite 连接或增加 SQLite 事务要求。
- 保持完整 manifest 与原 master 一致。新页面无需新的权限、host 权限、注入范围或 web accessible resources。

## 数据和容量验证

隔离数据库包含45万片段、约十万背景用户、2683633条片段日记录。最重用户有25000个片段，每个片段连续90天都有收获。测试只使用本地合成数据。

最新一分钟持续校验目标25 RPS，共1500个请求，HTTP错误为0，P95为6.84ms、P99为8.26ms。极端重度用户首次应用缓存未命中查询约1.90秒，六个混合并发请求全部成功。

“冷查询”只指应用缓存未命中，不代表清空了数据库或操作系统缓存。PostgreSQL容器内存限制512MiB，未额外限制CPU；应用和请求发生器在宿主机运行。这是本地容量证据，不是线上延迟或吞吐保证。复现脚本在服务端 `scripts/benchmark-contribution-stats.cjs`，结果在其 `working/contributions/benchmark.json`。

完整后端、前端和真实扩展测试结果汇总于 `ignored/contributions/verification.json`。真实限流集成检查使用独立本地服务，验证代理转发IP互相隔离、429 no-store，以及Redis store故障回退。
